Пункт **Туннель** в настройках заменяет колонку лаунчера на всю область. Исходник поведения — `TunnelPage.kt` и комментарий `TunnelOverrides.kt`. Страница не описывает правила брандмауэра: на `main` выбор узла пишется как адрес Roxy, а не как скрипт firewall.

## Что на экране

Первая строка — регион: **RU**, **EU**, **NA**, **SEA**, **NEA**.

Вторая строка, слева направо:

- **Измерить** — замер открытого региона. Выбранный сервер и `overrides.json` не меняет;
- **Найти лучший сервер** — если свежего успешного замера нет, сначала измеряет. Затем записывает один узел с лучшим показателем режима. Без ответа и на лимите не выбираются. Исключённые группы в кандидаты не входят;
- иконка обновления (круглый SVG, без подписи) — по нажатию крутится, список заново. Сервер, которого не было в прошлом списке, остаётся скрытым, пока не ответит. Промах убирает узел из пула;
- меню режима: **Пинг**, **RTT клиента**, **RTT сервера**, **Стабильность**. Это список в стиле страницы, не системный combo.

Над строками — подписи колонок **До вас**, **Пинг**. Колонка, по которой ищет «Найти лучший сервер», помечена. Стабильность тоже смотрит на пинг. Эти колонки и переключатели блока стоят в карточке группы. На 900×580 и 1280×760 подписи помещаются целиком.

Заголовок, панель действий и карточки групп — отдельные блоки, между ними зазор. Колонка настроек заполняет область контента: потолок 820 px снят. На окне 1280 px страница занимает всю ширину контента. Ширина боковой колонки — [Shell scale](../../architecture/shell/).

Группа — карточка: имя, число видимых узлов, справа **Исключить группу** (после применения — **Группа исключена**). Нажатие спрашивает подтверждение («Заблокировать N нод группы?» / «Вернуть N нод группы?»). **Отмена** закрывает его: исключения, список блокировки и брандмауэр остаются как были. Переключатель узла меняет один id сразу, без диалога. Клик по имени группы измеряет только её. Строки без годного IPv4 скрыты. Пулы `CLOUD-*` отфильтровываются до списка, замера и поиска.

Строка узла: замок (открыт, закрыт вместе с группой или лимит), точка узла, который записала бы «Найти лучший сервер», имя, два числа. Клик по доступной строке записывает override этого региона. Закрытый, исключённый или на лимите узел не выбирается.

Пустые фигуры — `—`. Нет ответа — подпись в колонке пинга. Шкала в подсказках строк: до 50 мс, до 100, выше 100. Потери и скачки за час тоже в подсказке, не отдельным абзацем.

## Каталог

Мок (`mockCatalog = !liveBackend`) читает список региона из classpath: `servers-ru.json` для RU, `servers.json` для остальных регионов (пулы с полем region), фикстура NEA. За этим списком мок в сеть не ходит. Live вызывает `TunnelCatalogs.fetch` по HTTPS, адреса каталога те же.

Пока каталога нет, над пустым списком не остаётся «Загружаю группы…». Три состояния — отдельные карточки:

- загрузка — «Загружаю группы…», пока список региона ещё в пути;
- ошибка — «Не удалось загрузить группы» и кнопка «Повторить»;
- пустой каталог — «Нет рабочих серверов». Если списка ещё нет и ошибки нет, карточка «Группы ещё не загружены» с кнопкой «Загрузить».

На моке открытый регион сразу показывает фикстуру. Разбор карточек — на страницах [Loading/error/empty](../../network/states/) и [Mock classpath](../../network/mock-catalog/).

## Куда это пишется

Игра читает один флаг на регион: `-Droxy_address_override.<region>=host:port`.

Выбор и режим поиска лежат в `jvm_wrapper/overrides.json`. Последние 20 замеров узла — в `jvm_wrapper/cache/tunnel_stats.json` и сбрасываются через 24 часа. На live каталог — `%APPDATA%\EXBO\jvm_wrapper`. На mock стол временный, системный профиль Windows страница не трогает.

Запуск проверяет сохранённый адрес. Каталог при запуске заново не качается и узлы не пингуются.
