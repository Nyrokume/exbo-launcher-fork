Пункт **JVM** открывает отдельную страницу. Над списком карточка сводки. Без выбора кикер «Сейчас», имя «не выбран», подсказка «Выберите конфигурацию ниже. Она запишется в запуск.» После клика кикер «Выбран для запуска», имя и heap (`v1.1.2, 6 ГБ`) и подсказка пресета. У выбранной сводки рамка `-primary`.

Кнопки-карточки в две колонки. На карточке видны версия с heap и подсказка пресета. У выбранной карточки рамка `-primary` и кольцо с заливкой `-primary`. Клик вызывает `StalzoneDesk.activatePreset`: пишет `configs/<id>.json` и делает этот id активным. Сообщение: «Профиль … записан. Перезапустите игру». Идентификатор `8khz` в подписи — «Профиль 8 кГц». Чужой id остаётся как есть.

`service.exe` читает активный профиль при следующем старте игры. Лаунчер IFEO не ставит.

## Пресеты

Порядок на странице — `JvmPresets.choices`. Первая карточка — **Без JVM**: `StalzoneDesk.useTunedProfile(false)` снимает активное имя, файл пресета не пишет. Сводка становится «Без JVM», подсказка «Игра запустится со своими флагами. Обёртка не подставит профиль.», сообщение «Запуск без профиля JVM. Перезапустите игру.»

Дальше идут профили, которые пишут файл. Генераторы взяты из EXBO-Community/stalcraft-jvm-optimization. На установленном лаунчере профиль собирается с этого компьютера: потоки, физические ядра, свободная память, медленная память (до 2933 МТ/с), большой L3 (от 64 МБ) и большие страницы, если привилегия уже включена. Неизвестная скорость памяти не считается медленной. Профили 8 кГц и Aikar остаются как записаны.

Под сводкой одна строка: процессор и видеокарта, число ядер, число потоков и объём. Медленная память, большой кэш и большие страницы дописываются в ту же строку, когда чтение их нашло. Витрина эту строку не показывает: `machine()` там пустой, чтобы снимки не плыли.

| Подпись | Id | Подсказка |
|---|---|---|
| Без JVM | пустой активный id | Игра запустится со своими флагами. Обёртка не подставит профиль. |
| Профиль 8 кГц | `8khz` | Короткие паузы G1, регионы 16 МБ |
| v1.1.2 | `v1.1.2/default` | Спокойные паузы G1 |
| v1.1.0 | `v1.1.0/default` | Короче паузы и дедупликация строк |
| v1.0.8 | `v1.0.8/default` | Спокойный JIT на слабом процессоре |
| v1.0.7 | `v1.0.7/default` | Не компилирует огромные методы на слабом процессоре |
| v1.0.4 | `v1.0.4/default` | Ранние флаги G1 |
| aikar | `aikar` | Флаги Aikar, пауза до 150 мс |

`build` по-прежнему принимает скрытые копии. Сохранённый `v1.1.1/default` подсвечивает карточку v1.1.2. `v1.0.5/default` и `v1.0.6/default` подсвечивают v1.0.4. Отдельных карточек у них нет.

Если генератор не выделяет heap (мало памяти), карточка выключена и подписана «Мало памяти для этого профиля». Карточка «Без JVM» остаётся включённой.

Шкала ОЗУ на странице лаунчера — от 2 ГБ до памяти машины, но не выше 8 ГБ, шаг 1 ГБ. Пометка «Мало памяти останется системе» появляется, только если системе останется меньше 2 ГБ. Когда значение шкалы уже выбрано, клик по пресету пишет этот heap вместо числа генератора и пересчитывает поля, которые от heap зависят (размер региона; на v1.0.x ещё metaspace, soft-ref и code cache). Флаги GC и JIT остаются. Пока шкала не выбрана, heap берёт генератор.

На live файл лежит в `%APPDATA%\EXBO\jvm_wrapper\configs`, активное имя — `HKCU\Software\StalcraftWrapper\ActiveConfig`. На mock это временный каталог и `MemoryRegistry`.
