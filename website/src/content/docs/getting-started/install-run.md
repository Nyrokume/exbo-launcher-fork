Нужен JDK 21. Wrapper уже лежит в корне репозитория, отдельно ставить Gradle не нужно.

## 1. Запустите лаунчер

```bash title="корень репозитория"
./gradlew run
./gradlew run -Dlauncher.lang=en
./gradlew build
./gradlew test
```

`test` идёт headless, X-сервер не нужен. На машине без дисплея живой запуск:

```bash
xvfb-run -a ./gradlew run -Dlauncher.screenshots=$PWD/docs/screenshots/zone
```

Аргументы `-Dlauncher.*` перечислены в [флагах запуска](../../reference/gradle-flags/).

## 2. Снимите экраны

```bash
./gradlew run "-Dlauncher.screenshots=docs/screenshots/zone" "-Dlauncher.animations=off"
```

PNG пишет автотур `ScreenshotTour` в указанный каталог. Тема по умолчанию — `zone`. Живой круг с анимациями: `-Dlauncher.showcase=true` (`docs/SHOWCASE.md`). Esc выходит из витрины.

В результате:

- в каталоге появляются `01_update_window.png` … `19_totp_error.png`;
- обои тура фиксированы (`03`), снимки повторяются.

Если окно не открылось, последовательно проверьте:

- установлен ли JDK 21 и совпадает ли он с `JAVA_HOME`;
- не занят ли дисплей; без него используйте `xvfb-run`.

:::tip
Для спора про вёрстку оставляйте mock. Live подключается сам, только когда клиент EXBO уже стоит на машине.
:::

## Мастер установки

`LauncherFork_Setup_<версия>.exe` ставит лаунчер для текущего пользователя и не запрашивает права администратора. В «Приложениях и возможностях» имя **EXBO Launcher**, издатель **EXBO**, игра **STALZONE**.

Порядок экранов совпадает с публичной справкой EXBO:

1. Выберите папку лаунчера. Кнопка обзора подписана «Изменить папку». По умолчанию `%LOCALAPPDATA%\LauncherFork`.
2. Нажмите «Далее». Итоговый путь всегда заканчивается на `\LauncherFork`. Папка `D:\Projects` становится `D:\Projects\LauncherFork`. Тихая установка `/S /D=...` следует тому же правилу.
3. Ярлык в меню «Пуск» создаётся всегда. Ярлык на рабочем столе необязателен: в мастере галочка включена, при тихой установке ярлык тоже создаётся.
4. Дождитесь окончания копирования.
5. На последнем экране можно запустить лаунчер. Игра скачивается уже из лаунчера, после входа.

Перед заменой файлов и ещё раз после копирования установщик сверяет SHA-256 каждого поставляемого файла. Несовпадение, отсутствующий файл или недоступный PowerShell останавливают установку с кодом выхода 3. Маркер `.launcherfork-install` в этом случае не пишется. Длины файла для проверки недостаточно. Папка, где уже есть `runtime` или `app`, но нет этого маркера, отклоняется с кодом выхода 2.

Ярлык с именем «EXBO Launcher» заменяется или удаляется, только если он указывает на этот `LauncherFork.exe`.

Удаление лаунчера оставляет на месте каталог игры, `%APPDATA%\EXBO` и `HKCU\SOFTWARE\EXBO` (`EXBO_SESSION`). Эти места установщик не пишет и не стирает.

:::caution[Имя без подписи совпадает с официальным лаунчером]
В «Приложениях и возможностях» издатель — EXBO, продукт — EXBO Launcher. Сертификата Authenticode в репозитории нет, файлы не подписываются (TODO). Это неофициальный форк, и без подписи его легко принять за официальный ExboLauncher.
:::

В открытой справке нет рисунка оригинального мастера, страницы лицензии и официального каталога по умолчанию, поэтому установщик их не копирует. Боковая картинка собрана из иконки форка.

Сборка на Windows — `packaging/build-installer.ps1`. На Linux `packaging/build-dist.sh` только компилирует exe: мастер там не открывается, SHA-256 при установке считает PowerShell на Windows.

## Дистрибутивы

`packaging/build-dist.sh` собирает каталог `dist/` (он в `.gitignore`):

| Файл | Что это |
|---|---|
| `LauncherFork_Setup_<версия>.exe` | Мастер NSIS, x64, без прав администратора. Папка, «Далее», установка. По умолчанию `%LOCALAPPDATA%\LauncherFork`. В системе имя EXBO Launcher |
| `LauncherFork_portable_win64.zip` | Тот же образ, запуск `LauncherFork.exe` |
| `LauncherFork_linux_x64.tar.gz` | jlink, запуск `bin/launcherfork` |
| `SHA256SUMS.txt` | Контрольные суммы |

`LauncherFork.exe` передаёт свои аргументы в JVM, например `-Dlauncher.lang=en`.

На Windows тот же установщик собирает `packaging/build-installer.ps1` (JDK 21 с `jlink`; OpenJFX и NSIS скрипт скачивает сам). С Linux `packaging/build-dist.sh` только компилирует exe. Шаги мастера и границы удаления — в разделе выше.

:::caution[Ассеты EXBO в истории git]
PNG из оригинального лаунчера и шрифт `Europe` принадлежат EXBO. README запрещает публичные сборки, пока эти файлы не заменены. Удаление из рабочего дерева историю не чистит.
:::
